# PaddleOCR-VL Windows 桌面应用（win-app）代码详解

> 本文档基于对 `win-app` 全量源码的通读整理，覆盖 Electron 主进程、渲染进程（Vue3）、Python sidecar 与构建分发配置。

## 1. 项目概述

- **定位**：PaddleOCR-VL 的 Windows 桌面端「扫描 + 拍照 + 文档识别」应用，离线整合包分发。
- **核心能力**：
  1. WIA 扫描仪采集（平板 / 自动送稿器 ADF），支持 JPEG/PNG/BMP/TIFF/PDF 输出；
  2. 摄像头拍照采集；
  3. 本地 OCR 识别（llama-server VLM + PaddleX 文档解析产线），支持批量队列；
  4. 结果导出：Word（.docx，公式转 OMML）、HTML、JSON、Markdown（含图片打包）；
  5. 工具箱：图片合并 PDF、图片格式批量转换；
  6. 无边框 Mica / 亚克力窗口（Win11 系统材质、Win10 FFI 亚克力）。
- **分发形态**：离线整合包（`resources/offline`），Python 虚拟环境、llama-server、Paddle 模型随包携带，应用内不引导在线安装。

## 2. 技术栈与依赖

| 层 | 技术 |
|---|---|
| 壳 | Electron ^33（contextIsolation 安全桥，无 nodeIntegration） |
| 窗口材质 | koffi（Win10 调 `SetWindowCompositionAttribute`）+ Electron `backgroundMaterial`（Win11 Acrylic） |
| 前端 | Vue3 `<script setup>` + Element Plus + marked + katex + DOMPurify |
| 构建 | Vite 5 + electron-builder 25（nsis + zip） |
| Python sidecar | 系统 venv Python，脚本位于 `electron/python/`，依赖 PyMuPDF(fitz)、PaddleOCR-VL 产线 |

## 4. 进程架构

```
┌────────────────────────── Electron 主进程（main.js） ──────────────────────────┐
│ 窗口 / 设置持久化 / IPC / Python sidecar 调度 / ServiceManager（services.js）     │
│        │ stdin(JSON)                       │ spawn                         │
│        ▼                                  ▼                               │
│  scan_worker.py ──HTTP──► paddlex serve(:8080) ──► 文档解析(布局/OCR/表格)     │
│         │                                  │                                │
│         ▼                                  ▼                                │
│  llama-server(:8081) ◄──HTTP── 公式/长文识别（VLM，GGUF 量化模型）              │
└──────────────▲───────────────────────────────────────────────────────────────┘
               │ contextBridge（preload.js 暴露 window.api）
┌──────────────┴──────────────── Vue3 渲染进程 ─────────────────────────────────┐
│ App.vue 导航壳 → Home/Acquire/DocTools/Convert（KeepAlive 保留状态）             │
│ store.js 全局响应式状态；useOcrQueue 任务队列；Element Plus UI                     │
└────────────────────────────────────────────────────────────────────────────────┘
```

数据流要点：渲染进程与本地文件系统隔离，图片通过 `img:data`（base64）读取；Python 脚本的参数经 **stdin 传 JSON**（规避 Windows 命令行引号转义问题），结果以 **JSONL 流式**返回（`{"t":"progress"|"result", ...}`）。

## 5. 主进程（electron/main.js）

### 5.1 路径解析与整合包判定

- 开发 / 打包双路径：`pyScriptsDir`、`projectRoot`、`offlineRoot()` 随 `app.isPackaged` 切换；
- `offlinePresent()`：`offline/python/python.exe` 存在即视为整合包分发（**无论完整性**，只提示缺失、绝不引导在线安装）；
- `bundledReady()`：Python + `llama.cpp/llama-server.exe` + `paddlex-models` + `models/gguf/*.gguf` 四者齐备才算完整；
- `resolvePaddleRoot()`：产线 yaml 与 wordrender.py 的定位（打包版放 resources，开发版用项目根）。

### 5.2 设置持久化（零依赖 JSON）

- `DEFAULT_SETTINGS`：服务（apiUrl/timeout/precision/device/paddleDevice/maxParallel）、VLM（ctxSize=32768/noCudaGraph/pdfRenderDpi=288）、目录（photoDir/scanDir/ocrDir/pdfOutDir）、识别默认值（defaults：开关、max_new_tokens、repetition_penalty、keep_source_dir、skip_existing 等）；
- `readSettings()`：合并用户 JSON → 默认值，并对 `ctxSize`（1024–131072）与 `pdfRenderDpi`（72–600）做范围钳制，防乱填搞挂服务；
- `saveSettings()`：`deepMerge` 合并，**`null` 值 = 恢复默认**（删除键使 readSettings 回退）；
- 默认目录规则：照片 → `图片库/本机照片`，扫描 → `文档/已扫描的文档`，OCR → `文档/OCR扫描结果`，PDF 输出 → `文档/PDF输出`，读不到配置时自动创建目录。

### 5.3 窗口

- Win11：`backgroundMaterial:'acrylic'` + `roundedCorners`，非透明窗口以获取系统圆角与材质；
- Win10 1809+：透明窗口 + `SetWindowCompositionAttribute(ACCENT)`（acrylic.js），CSS 模拟圆角；
- 启动时若整合包完整，`createWindow` 内后台预热模型（`services.start()`，不阻塞 UI）。

### 5.4 Python sidecar 执行器（runPython）

- `spawn(python, args)`，`cwd` 打包版为 userData / 开发版为 win-app 根；
- stdout 按行解析 JSON：`t=result` 记为 final（其余为事件），`t=progress` 转发给渲染进程；stderr 转发为 `ev:log`；
- `final` 存在即 resolve `{...result, events}`，否则按退出码 reject。

### 5.5 IPC 清单

| 通道 | 用途 |
|---|---|
| `sys:info` / `sys:default-dirs` / `sys:reveal` / `sys:open-external` | 系统信息、默认目录、资源管理器定位、外链 |
| `sys:open-dir` / `sys:path-exists` | 打开目录（不存在自动创建，`shell.openPath` 跨平台）/ 判断路径是否存在 |
| `settings:get` / `settings:save` | 设置读写（保存后立即 `emitStatus` 刷新服务状态） |
| `backend:status/start/warmup/stop/log` | 服务管理 |
| `setup:status` / `sys:missing-files` | 环境向导 / 缺文件原生错误弹窗 |
| `scan:parse` / `export:render` | 识别（模式 `parse`）/ 缓存重导出（模式 `render`） |
| `scan:pdf-preview` | PDF 缩略图（写 `%TEMP%\paddleocr_preview_*`，退出清理；可传页数上限，只渲染前 N 页） |
| `scan:devices/preview/run/default-dir` | WIA 扫描 |
| `pdf:merge` / `img:apply` / `img:save-data` / `img:data` | 工具箱 / 摄像头 / 图片读取（TIFF 自动转 PNG 供浏览器渲染） |
| `dlg:files/folder/dir/save` | 文件对话框 |
| `fs:list-files` | 目录递归列举（支持 jpg/png/bmp/tif/webp/pdf） |
| `clipboard:write` | 剪贴板（file:// 非安全上下文下 navigator.clipboard 不可用） |
| `win:min/max/close` / `app:quit` | 窗口控制 / 致命错误退出 |

### 5.6 生命周期

- 单实例锁（`requestSingleInstanceLock`），二次启动聚焦已有窗口；
- `whenReady`：先 `cleanupTempScans()` 兜底清理上次异常退出（崩溃/强制结束）残留的临时文件（此刻无 sidecar 运行，均为可再生成产物）→ 授予摄像头/麦克风权限 → 建窗 → 每 5s 兜底推送服务状态 → 环境就绪自动启动服务；
- `window-all-closed` / `before-quit`：按 `keepServicesAfterQuit` 决定是否停服务，并清理 `%TEMP%` 下 `paddleocr_scan_*` / `paddleocr_preview_*` / `paddleocr_imgtool_*` / `paddleocr_cam_*` / `paddleocr_tif2png_*` 及 `outputs/.previews/` 残留。

## 6. 服务管理器（electron/services.js）

`ServiceManager` 负责拉起与守护两个本地服务：

| 服务 | 端口 | 进程 | 说明 |
|---|---|---|---|
| PaddleX | 8080 | `python -m paddlex --serve --pipeline <yaml>` | 文档解析：布局/OCR/表格/方向 |
| llama-server | 8081 | `llama-server -m gguf --mmproj ...` | VLM：公式与长文识别 |

关键设计：

- **GPU 探测**：`probeGpu()` 调 nvidia-smi（6s 超时），计算能力 ≥7.5 才启用 GPU；CPU 模式下 `CUDA_VISIBLE_DEVICES=''` 屏蔽 CUDA、`-ngl 0`；
- **产线配置**：整合包模式 `writeOfflineYaml()` 用正则把 yaml 中 `model_dir: null` 改写为 `paddlex-models/<模型>`，paddle 与 llama 设备独立可控（`device` / `paddleDevice`）；
- **llama 启动参数**（针对公式识别专门调参）：
  - `-c` = ctxSize（默认 32768，避免图片视觉 token + 长 LaTeX 超上下文被截断导致 `\frac`/`\genfrac` 退化成线性文本）；
  - `--temp 0` 贪心解码（对齐 Docker 版，稳定量化模型输出）；
  - **不设 repeat-penalty**（LaTeX 含大量重复的 `\ { } frac` token，复读惩罚会使其退化）；
  - `--no-cuda-graph` 可选（省显存）；复用 Paddle venv 的 CUDA 12.9 运行时（PATH 前置 nvidia/bin）；
- **模型量化**：非 fp16 精度按需 `ensureQuantized()`（llama-quantize），同精度并发去重（`quantizePromise`），产物 `models/gguf/*.gguf` 一次性复用；
- **端口占用检测**：启动前探测 8080/8081——被本应用保留（PID 文件）则复用，否则报端口冲突，避免状态栏误显示"已就绪"却打到他人服务；
- **latched 状态**：端口曾就绪后进程存活期间保持 `latched=true`，识别中不被瞬时抖动误判；
- **启动互斥**：`start()` 以 `startPromise` 去重，启动预热/自动启动/用户点击并发触发共享同一流程，避免重复 spawn；`stop()` 置空锁，允许下次重新启动；
- **PID 持久化**：`keepServicesAfterQuit` 时把服务 PID 写入 `services-pids.json`，重启后跨会话复用，停止时按文件清理；
- `readLog` 返回日志尾部（60KB）供设置页查看。

## 7. Python sidecar 脚本

### 7.1 scan_worker.py（识别主脚本）

- **入参**：`<mode: parse|render> <file> <out_dir 或 '-' > <python_root> <output_root>`，请求 JSON 经 stdin；
- **两种模式**：
  - `parse`（完整识别）：构建 payload → POST `/layout-parsing` → 解析返回 → 生成 md/docx/html/json/图片 → 打包 zip；
  - `render`（缓存重导出）：前端已缓存 md/images，直接本地渲染，不重跑 VLM；
- 请求参数映射产线字段：`use_seal / use_chart / use_orientation / use_unwarping / use_ocr_image_block / format_block_content / use_layout_detection / merge_layout_blocks / max_new_tokens / repetition_penalty / max_pixels / min_pixels`，以及 `pdf_per_page`、`export_chart`、`keep_source_dir`、`skip_existing`；
- **PDF**：`render_pdf_pages()`（PyMuPDF）按 `pdfRenderDpi/72` 缩放渲染成临时 PNG 逐页识别；`per_page` 开启时逐页出结果；
- **表格图片裁剪**：`export_chart` 时 `crop_chart_images()` 裁剪文档中的图表区域；
- **Word 导出**：`_md_to_docx_python()` 调 `wordrender.py`，LaTeX 公式 → OMML（含 `\frac / \genfrac / cases` 等处理）；
- **HTML 导出**：`_md_to_html()`（markdown + bs4 + latex2mathml）内嵌图片 base64；
- 网络重试：`http_post()` 对 ConnectionError 重试 3 次（服务加载期间容错）；
- 结果以 `{"t":"result","ok":...,"status":...,"download":...,"md":...,"images":...,"pages":...,"elapsed":...}` 输出，`download` 指向结果 zip/docx 绝对路径。

### 7.2 scan_device.py（WIA 扫描仪）

- `devices`：枚举扫描仪（名称/颜色能力/ADF 支持）；
- `preview`：固定 100dpi 低分辨率快速预览（写 `%TEMP%\paddleocr_preview_*`；与正式扫描 DPI 解耦，几秒出图）；
- `scan`：参数 `--dpi --mode(color/gray/black) --format --source(flatbed/adf) --pages(0=自动) --enhance --outdir --name`；
  - ADF 自动模式：循环取页直至纸空，按"部分成功"逻辑收尾；
  - 多页：JPG/PNG/BMP 逐页落盘，PDF/TIFF 合流导出；
  - `--enhance`：可选调 paddlex 做自动转正 / 智能取景（`fetch_orientation`）；
- 全程经 `paddleocr_scan_*` 临时目录，退出时由主进程统一清理。

### 7.3 pdf_preview.py

- 把 PDF 逐页渲染为 JPEG 缩略图（`paddleocr_preview_*` 前缀目录），供结果查看器「原图」标签与获取页托盘预览使用；支持 `--max-pages N` 只渲染前 N 页（获取页大图预览仅需首页，避免整本渲染）。

### 7.4 merge_to_pdf.py

- 图片按序合并 PDF，`--dpi` 换算缩放（scale = 72/dpi），供工具箱「图片 → PDF」使用。

### 7.5 image_tool.py

- `--ops`（stdin JSON 操作序列）+ `--convert` 输出格式：
  - 基础：旋转/缩放/裁剪/去色/二值化/反色/调节亮对比度/高斯模糊/锐化/美颜；
  - 扫描仪效果：`auto-orient`（自动转正）、`layout-scan`（PPDocLayout 智能取景）——需 paddlex 服务可用（传 `--api`）。

## 8. 渲染进程

### 8.1 store.js（全局状态）

- `settings / sys / backend / setup`：应用配置与系统/服务状态；
- `results: {}`：识别结果缓存 `{md, images, imgUris, download, prunedResults}`（跨模块共享）；
- `acquireTray`：获取页托盘；`ocrInbox`：待识别文件路径（托盘/摄像头 → 文档识别）；
- `running / stopRequested`：批量处理状态；
- 工具函数：`inlineImages()`（`<img src="imgs/x.jpg">` → data URI，base64 头嗅探 MIME）、`statusLabel()`、`log()`（环形日志 500 条）。

### 8.2 App.vue（应用壳）

- **导航**：`home / acquire / doc / convert` 四模块 KeepAlive 缓存工作状态；`acquireTab` 子标签（scanner/camera）；旧模块名（scan/camera）兼容映射；
- **记住上次位置**：`rememberLastModule` 关闭时永远回首页，开启时才从 localStorage 恢复（默认关）；
- **整合包阻断**：`refreshSetup()` 检测 `bundledComplete`——不完整则弹系统级「文件缺失错误」模态框（提示重新安装）、主界面被 `needSetup` 阻塞，向导仅提供「重新检查 / 退出应用」，无「仍然继续」入口（本次已修复）；
- **后端状态订阅**：`onBackendStatus` 实时同步到 `store.backend`；
- **平台差异**：Win10（build<22000）自动切 `.platform-win10` 方角布局，避免圆角空洞。

### 8.4 composables

- **useOcrQueue.js**（核心队列逻辑）：
  - 状态机：`wait → run → done | fail | stop`；`selectedPath` 以路径标识（避免索引错位）；
  - 批量识别：并发取 `maxParallel`（默认 1=串行），循环拾取 wait 项实现**自动续跑**；`store.running` 全局唯一，服务未启动时先 `startBackend()` 并 `waitBackendReady`（600s 超时）；
  - 运行中移除的项不回写结果/不报错（防"复活"）；清空队列同时清空结果缓存释放内存；
  - `exportMode()`：优先用缓存 md/images 走 `export:render` 免重跑（JSON 需 prunedResults，识别时已缓存）；经 IPC 前对响应式对象做深拷贝（避免 "An object could not be cloned"）；
  - 结果缓存后异步 `loadImagesFor()` 生成原图预览（PDF 用 pdf_preview 逐页）——预览失败仅记日志，**不阻断自动保存**；
  - **自动扫描**（autoScan 开启且勾选导出格式）：识别完成即逐个导出（复用缓存走 `export:render`），成功日志带**完整输出路径**，失败弹 `ElMessage` 提示（不再静默进日志）；开启时提示保存位置。
- **useBackendStatus.js**：启动时拉取一次状态 + 订阅 `ev:backend-status` 推送。

## 9. 关键业务流程

### 9.1 应用启动

```
whenReady → 授予媒体权限 → createWindow（Win11 Acrylic / Win10 FFI）
  ├─ 整合包完整 → 后台预热 services.start()
  └─ 渲染进程 onMounted：getSystemInfo → getSettings → restoreModule
       → getBackendStatus → refreshSetup(autoOpen)
  └─ 若 bundledComplete=false → 原生错误框 + 向导阻断（退出/重新检查）
  └─ 环境就绪 → 自动拉起服务（auto-start）
```

### 9.2 服务生命周期

```
start（互斥锁）→ 端口占用检测（PID 文件裁决）→ 复用已存活服务
  → 模型精度匹配（无则按需量化 ensureQuantized）
  → probeGpu（CC≥7.5）决定 llama(-ngl 99/0) 与 paddlex(--device gpu:0/cpu)
  → spawn llama-server + paddlex serve → waitPorts(600s) → emitStatus
stop → kill procs + PID 文件进程 → 清 latched → 置空互斥锁
```

### 9.3 扫描 → 识别

```
ScanConsole.doScan → scan:run → scan_device.py（WIA，ADF 自动页）
  → 结果页/文件入 acquireTray（PDF 模式入临时 PNG 缩略图）
  → 识别全部/此页 → ocrInbox → DocTools watch 自动入队 → useOcrQueue
  → 服务未就绪先拉起 → 并发 maxParallel 逐项 parse → 结果缓存 → 预览图
  → 自动扫描（autoScan）开启：识别完成即按勾选格式导出到 OCR 输出目录
```

### 9.4 导出

```
Word/HTML/JSON/Markdown 按钮 → exportMode(mode)
  有缓存(md/images/prunedResults) → export:render（本地渲染，免重跑）
  无缓存（JSON 缺结构化）→ parse（完整识别）
  → 完成后 revealPath 打开所在目录
```

## 11. 已知问题与注意事项

### 本次会话已修复

1. **向导「仍然继续」白屏**：整合包缺文件时改为直接弹「文件缺失错误」模态框并只提供「重新检查 / 退出应用」（App.vue + FirstRunWizard.vue + main.js `app:quit`）。
2. **扫描输出目录与设置脱节**：移除 `localStorage('scan.outdir')`，面板默认取设置「扫描结果保存位置」，设置变更实时跟随（手动指定过的本次会话不覆盖）。
3. **摄像头照片回退目录**：默认保存到「本机照片」，不再回退到扫描目录。
4. **服务启动无互斥**：`start()` 增加 `startPromise` 锁，并发启动共享同一流程。
5. **自动模式结果缺失**：原图预览 `loadImagesFor` 抛异常会被 worker catch 吞掉，导致后续自动保存被跳过且无提示；修复为预览失败不阻断自动保存、导出失败弹 `ElMessage`、成功日志带完整输出路径、开启时提示保存位置。
6. **大图预览格式兼容**：获取页「页面查看」区补齐 TIFF（`img:data` 用 PIL 转 PNG）与 PDF（PyMuPDF 渲染首页）预览，覆盖扫描仪全部导出格式。
7. **结果文件夹快速打开**：DocTools 自动扫描工具条新增「结果文件夹」按钮（`sys:open-dir`，跨平台、目录不存在自动创建）。
8. **缓存清理补漏**：TIFF 转换临时文件 `paddleocr_tif2png_*` 纳入退出清理前缀；启动时 `cleanupTempScans()` 兜底清理异常退出残留。

### 遗留低危问题（可选优化）

- HTML 导出依赖 `markdown/bs4/latex2mathml`，缺失时 zip 内无 .html 但提示成功——建议缺失时明确报错；
- Word 渲染失败时报「不支持的导出模式」误导性文案——建议直接报告 Word 生成失败原因；
- 每次导出新建 `%Y%m%d_%H%M%S_uuid` 独立目录，重复导出会累积目录；
- 首页「启动 OCR 服务」按钮在 `waitPorts`（最长 600s）期间无进度提示；
- 批量格式转换仅查批次内重名，磁盘上已存在的同名文件会被覆盖。

## 12. 安全与健壮性小结

- 渲染进程 `contextIsolation: true` + `nodeIntegration: false`，文件访问全部经 IPC 白名单；
- 结果渲染经 DOMPurify 净化，防 XSS；
- 图片/文件名做了扩展名限制与唯一化处理；
- 单实例锁、端口占用检测、PID 跨会话复用/清理、`%TEMP%` 残留清理、GPU 探测回退、参数范围钳制均有覆盖。
